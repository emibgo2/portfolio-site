# 고지훈 · Backend & Infrastructure Engineer — 포트폴리오

ADR(의사결정 기록) + 인시던트 아카이브 + 3단 읽기 깊이 조합의 정적 포트폴리오입니다.

## 파일

```
index.html    # 페이지 구조 + 렌더 엔진 (약 420줄)
styles.css    # 디자인 시스템 (토큰 · 레이아웃 · 도식 · 인쇄)
data.js       # 콘텐츠 전체 + SVG 도식 13개
og-image.svg  # 공유 미리보기 (카카오톡 · 슬랙 · X)
README.md     # 이 문서
```

빌드 도구, npm, 서버 런타임이 필요 없습니다. 본문은 외부 의존성 없이 동작하고, 히어로 3D 그래프만 첫 화면 렌더 후 Three.js와 SVGLoader를 지연 로드합니다.

## 보는 방법

**1) 그냥 열기** — `index.html` 더블클릭.

**2) 로컬 서버** (브라우저 보안 정책 회피용)
```bash
cd portfolio-site
python3 -m http.server 8000    # http://localhost:8000
```

**3) GitHub Pages 배포**
```bash
git init && git add . && git commit -m "portfolio"
git branch -M main
git remote add origin https://github.com/emibgo2/portfolio.git
git push -u origin main
```
저장소 → Settings → Pages → Source: `Deploy from a branch` → `main` / `/ (root)`.
→ `https://emibgo2.github.io/portfolio/`

**4) 본인 인프라에 ArgoCD로** — 이 사이트를 컨테이너로 만들어 클러스터에 올리면
"사이트 자체가 증거"가 됩니다. `Dockerfile`(nginx:alpine + 정적 파일) + `manifests/app.yaml` +
ArgoCD Application을 추가하고, `/about`의 "이 페이지는 이렇게 동작합니다"에 링크를 걸어두세요.

## 콘텐츠 수정

`data.js` 한 파일만 고치면 됩니다. HTML을 건드릴 필요가 없습니다.

| 객체 | 내용 |
|---|---|
| `profile` | 이름, KPI 5개, 연락 링크 |
| `sections` | 좌측 목차 |
| `systems` | 프로젝트 10개 — `thesis`(한 줄 주장), `story`(문제/판단/실행/결과/남은 것), `metrics`, `diagram`(도식 + 질문 + 캡션), `tags`, `refs` |
| `decisions` | ADR 15개 — `sum`, `context`, `alts`(마지막 항목이 채택안), `consequences`, `gave` |
| `incidents` | 장애·실험·예방 개선 팝업 7건 — `impact`, `detect`, `cause`, `action`, `result`, `prevent`, `verify` |
| `runbooks` | 런북 5개 |
| `stack` | 기술 스택 6그룹 (3번째 배열에 넣은 항목이 강조됨) |
| `about` | 소개 문단, 경력, 활동·수상, 사이트 설명 |

`story`, `sum`, `thesis` 등에서 `<b>` `<em>` 정도의 인라인 태그를 쓸 수 있습니다.

## 3단 읽기 깊이

데이터는 하나이고 뷰의 밀도만 바꿉니다. 선택은 브라우저에 저장됩니다.

| 깊이 | 보이는 것 |
|---|---|
| **30초** | 프로젝트 제목 · 기간 · 한 줄 주장, 장애 요약 |
| **3분** | + 문제/판단/실행/결과, 결과 지표, 도식, 프로젝트별 설계 판단 팝업 |
| **30분** | + "남은 것", 심화 도식, 고려한 대안 전체, 장애 탐지·조치·검증·재발 방지, 활동·수상 |

채용 담당자가 30초로 훑고, 기술 면접관이 30분으로 들어오는 구조입니다.

## 서사 구조

프로젝트마다 이 순서로 씁니다. 좋은 케이스 스터디 11편의 공통 구조를 따랐습니다.

```
한 줄 주장  → 이 프로젝트가 무엇을 증명하는가
문제        → 어떤 신호로 문제를 알았는가 (숫자와 장면)
판단        → 어떤 대안을 검토했고 왜 이걸 골랐는가
실행        → 실제로 무엇을 했는가
결과        → 측정 가능한 변화
남은 것     → 감수한 대가와 아직 위험한 부분
```

ADR은 `맥락 → 대안(✕/→) → 결과 → 대가`, 인시던트는
`탐지 → 직접 원인 → 조치 → 결과 → 검증 → 재발 방지`로 통일했습니다.

## 도식 13개

모두 인라인 SVG입니다. 이미지 파일도, 외부 라이브러리도 쓰지 않습니다.
`data.js`의 `G` 헬퍼(`node`, `group`, `v`, `h`, `elbow`, `bar`, `strike`, `note`)로 좌표만 잡으면 됩니다.

1. SSO 인증 흐름 · 2. K8s/DR 토폴로지 · 3. GitOps 배포 파이프라인 · 4. 라이선스 정책 검증 ·
5. 인프라 개편 AS-IS/TO-BE · 6. DR 복구 타임라인 · 7. 로깅 파이프라인 · 8. 테스트 CI 분리 ·
9. 폐쇄망 앱 알림 · 10. 검증 중앙화 AS-IS/TO-BE (WizRAMS) · 11. 슬로우 쿼리 실행 계획 비교 ·
12. 헌혈 매칭 흐름 · 13. 개인 서버 로그 파이프라인 (Mongle)

도식 규칙: 제목을 질문으로 쓸 것, 화살표에 의미를 적을 것, AS-IS/TO-BE는 같은 위치에서 비교할 것,
모든 도식에 캡션을 붙일 것. 좁은 화면(≤900px)에서는 글자가 작아지지 않도록 도식만 가로 스크롤됩니다.

## 적용한 디자인 기준

레퍼런스 실측값을 기준으로 잡았습니다.

- **섹션 리듬** 96 → 128px, 컴포넌트 간격은 4px/8px 배수
- **읽기 폭** 본문 720px, 도식 720px, 바깥 셸 1180px
- **타입** 본문 15~16px / 1.72, 섹션 라벨 13px 대문자 + 0.16em 자간, 제목 -0.02~-0.035em 트래킹
- **색** 배경 1 + 본문 1 + 보조 회색 3단 + 강조 1. 계층은 색이 아니라 불투명도로
- **목록** 상시 카드 대신 헤어라인 경계선. hover 시 이웃이 아니라 대상만 반응
- **모션** 150~300ms `cubic-bezier(.4,0,.2,1)`. `prefers-reduced-motion`이면 전부 정지
- **상호작용** 깊이 토글, 설계 판단 팝업, 장애·예방 개선 팝업, 읽기 진행률, 흩어진 3D 기술 로고 필드

## 의도적으로 뺀 것

휴대폰 번호, 집 주소, 생년월일, 희망 연봉은 넣지 않았습니다(공개 페이지 기준).
회사명과 공개 가능한 수치만 사용했고, 코드·내부 문서·고객 데이터는 포함하지 않았습니다.

## 아직 안 한 것

1. **실제 배포** — 지금은 로컬 파일 상태입니다
2. **OG 이미지 PNG** — `og-image.svg`는 코드 기반 미리보기용입니다. 카카오톡·슬랙 등 일부 크롤러는 PNG만 인식하므로, 배포 전에 1200×630 PNG로 변환해 `og-image.png`로 두고 메타를 바꾸면 호환성이 높아집니다
3. **영문 버전** — 외국계 지원을 염두에 두면 문단 병기 또는 언어 토글
4. **이력서 PDF 링크** — 인쇄 스타일이 있으니 `Cmd+P → PDF` 후 `/resume.pdf`로 올려 링크
5. **데이터 분리** — 필요하면 `data.js`를 JSON으로 바꿔 백엔드에서 내려줄 수도 있습니다

## 검증한 것

- 렌더링: 시스템 10 / 설계 판단 팝업 15 / 장애·실험·예방 개선 팝업 7 / 런북 5 / 스택 6 / 도식 13, 콘솔 에러 0
- 3단 깊이 전환, 설계 판단·장애 팝업 열기·닫기, 목차 활성화, 진행률 동작 확인
- 도식 13개 텍스트가 노드 밖으로 넘치지 않고 viewBox를 벗어나지 않음 (좌표 검사, 이슈 0)
- 도식 라벨 실측 크기 11.2px (데스크톱) / 9.8px (390px, 가로 스크롤)
- 가로 스크롤 없음 (1440 / 768 / 390px), 인쇄 시 전 깊이 펼침 + 흰 배경 전환
- 본문 초기 렌더 외부 요청 0건, 3D 그래프는 첫 화면 렌더 후 필요한 모듈만 지연 요청
