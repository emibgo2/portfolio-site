# 고지훈 · Software Engineer — 포트폴리오

ADR(의사결정 기록) + 인시던트 아카이브 + 2단 읽기 깊이 조합의 정적 포트폴리오입니다.

## 파일

```
index.html    # 페이지 구조 + 렌더 엔진 (약 420줄)
styles.css    # 디자인 시스템 (토큰 · 레이아웃 · 도식 · 인쇄)
data.js       # 콘텐츠 전체 + SVG 도식 12개
og-image.svg  # 공유 미리보기 (카카오톡 · 슬랙 · X)
output/pdf/go-jihoon-portfolio.pdf # 다운로드용 30분 상세본
resume.html   # 주요 업무·성과 중심 이력서 원본
resume.css    # 이력서 화면·A4 인쇄 양식
output/pdf/go-jihoon-resume.pdf # 다운로드용 이력서
README.md     # 이 문서
```

빌드 도구, npm, 서버 런타임이 필요 없습니다. 본문은 외부 의존성 없이 동작하고, 히어로 3D 그래프만 첫 화면 렌더 후 Three.js와 SVGLoader를 지연 로드합니다.

## 보는 방법

**1) 그냥 열기** — `index.html` 더블클릭.

**2) 로컬 서버** (브라우저 보안 정책 회피용)
```bash
cd portfolio-site
python3 -m http.server 8000    # http://localhost:8000
```

**3) GitHub Pages 배포**

- 저장소: `emibgo2/portfolio-site`
- 배포 원본: `main` 브랜치의 `/ (root)`
- 사이트 주소: `https://emibgo2.github.io/portfolio-site/`
- `.nojekyll`로 Jekyll 처리를 생략하고 정적 파일을 그대로 게시합니다.

Pages 설정 후에는 검증한 변경사항을 커밋하고 `main`에 푸시하면 자동으로 배포됩니다.

```bash
git push origin main
```

저장소의 **Settings → Pages**에서 배포 원본을, **Actions**에서 배포 결과를 확인합니다.

## 콘텐츠 수정

웹 포트폴리오 본문은 `data.js`에서 수정합니다. 요약 이력서는 `resume.html`에서 별도로 편집하며, PDF 갱신 방법은 아래를 참고하세요.

| 객체 | 내용 |
|---|---|
| `profile` | 이름, 핵심 역량 4개, 연락 링크 |
| `sections` | 좌측 목차 |
| `systems` | 프로젝트 9개 — `thesis`(한 줄 주장), `story`(3분 핵심 정리), `storyDetail`(30분 상세 설명), `metrics`, `diagram`(도식 + 질문 + 캡션), `tags`, `refs` |
| `decisions` | ADR 13개 — `sum`, `context`, `alts`(마지막 항목이 채택안), `consequences` |
| `incidents` | 장애·실험·예방 개선 팝업 7건 — `impact`, `detect`, `cause`, `action`, `result`, `prevent`, `verify` |
| `runbooks` | 런북 5개 |
| `stack` | 기술 스택 6그룹 (3번째 배열에 넣은 항목이 강조됨) |
| `about` | 소개 문단, 경력, 활동·수상, 사이트 설명 |

`story`는 [라벨, 항목 배열]을 목록으로, [라벨, 문자열]을 짧은 설명으로 표시합니다. 목록과 설명에는 `<b>` `<em>` 등 인라인 태그를 쓸 수 있습니다.
설명 본문은 마침표와 지정한 의미 단위에서 줄바꿈합니다. 문장별 줄 길이를 균형 있게 배치하고 한국어 단어 중간의 끊김을 방지합니다. 소수점·URL은 유지하며, 3분·30분 본문과 상세 기록 팝업에 같은 규칙을 적용합니다.

## 2단 읽기 깊이

읽기 깊이는 프로젝트 섹션 안의 내용에만 적용합니다. 소개·경력·활동·수상·학력·런북·스킬은 두 모드에서 동일하게 표시합니다. 페이지를 새로 열면 항상 30분으로 시작하며, 페이지 안에서 3분과 30분을 전환할 수 있습니다.

| 깊이 | 프로젝트 섹션에서 보이는 것 |
|---|---|
| **3분** | 프로젝트 제목 · 기간 · 한 줄 주장, 문제/실행/결과와 필요한 설명, 결과 지표, 도식, 프로젝트별 설계 판단 팝업 |
| **30분** | 문제·선택 이유·구현 과정·성과의 상세 설명, 결과 지표, 기본·심화 도식, 프로젝트별 설계 판단 팝업 |

3분은 `story`, 30분은 `storyDetail`을 표시합니다. 본문 두 버전을 함께 나열하지 않으며, 인쇄 시에는 상세 설명만 출력합니다.

## PDF 다운로드

상단의 **PDF 다운로드**를 누르면 이력서와 포트폴리오를 선택할 수 있습니다.

| 선택 | 원본 | 다운로드 파일 |
|---|---|---|
| **이력서** | `resume.html` · `resume.css` | `output/pdf/go-jihoon-resume.pdf` |
| **포트폴리오** | `index.html` · `data.js` · `styles.css` | `output/pdf/go-jihoon-portfolio.pdf` |

이력서는 기본 정보·기술 스택·회사별 주요 업무와 성과·기타 개발 경험·학력·활동으로 정리한 3쪽 문서입니다. 회사별 경력 안에서는 설계·개발, DB·성능 개선, 인프라·운영, 배포·품질 관리 등 업무 영역별로 수행한 일을 묶고, 프로젝트명은 필요한 항목 안에서만 언급합니다. 철도시설 성능평가 통합 시스템 업무는 네모시스 경력에 포함합니다. 포트폴리오는 상세 설명과 도식을 담은 30분 버전입니다.

내용을 변경하면 해당 원본을 브라우저에서 열고 `Cmd/Ctrl+P` → 용지 `A4` → `배경 그래픽` 켜기 → `PDF로 저장`으로 다운로드 파일도 갱신합니다. 이력서는 본인의 랠릿 이력서에 있는 담당 업무·프로젝트 경험과 `data.js`의 최신 경력·성과를 함께 반영합니다. 서로 다른 시점의 수치나 기간은 최신 확인 내용을 우선하며, 이력서 본문은 `resume.html`에서 관리합니다. PDF를 교체할 때는 `index.html`의 해당 다운로드 링크 버전 값도 올려 이전 파일이 캐시에 남지 않게 합니다.

## 서사 구조

3분 본문은 목록으로 정리하고, 선택 이유·측정 조건처럼 설명이 필요한 곳에만 짧은 문장을 덧붙입니다. 한 프로젝트의 문제·실행·결과는 각각 한곳에 모아 나열합니다. 30분 본문은 선택 이유와 구현 과정을 상세히 설명합니다. 실제 수행한 운영·검증 작업은 실행이나 결과에 포함합니다.

```
한 줄 주장  → 프로젝트의 핵심
문제        → 기존 상태와 문제
실행        → 해결을 위해 수행한 작업
결과        → 개선 결과 (목표·진행 중인 항목은 구분)
필요한 설명 → 선택 이유·측정 조건·근거
```

ADR은 `맥락 → 대안(✕/→) → 결과`, 인시던트는
`탐지 → 직접 원인 → 조치 → 결과 → 검증 → 재발 방지`로 통일했습니다.

## 도식 12개

모두 인라인 SVG입니다. 이미지 파일도, 외부 라이브러리도 쓰지 않습니다.
`data.js`의 `G` 헬퍼(`node`, `group`, `v`, `h`, `elbow`, `bar`, `strike`, `note`)로 좌표만 잡으면 됩니다.

1. SSO 인증 흐름 · 2. K8s/DR 토폴로지 · 3. GitOps 배포 파이프라인 · 4. 라이선스 정책 검증 ·
5. 인프라 개편 AS-IS/TO-BE · 6. DR 복구 타임라인 · 7. 로깅 파이프라인 · 8. 테스트 CI 분리 ·
9. 폐쇄망 앱 알림 · 10. 검증 중앙화 AS-IS/TO-BE (WizRAMS) · 11. 슬로우 쿼리 실행 계획 비교 ·
12. 헌혈 매칭 흐름 · 13. 개인 서버 로그 파이프라인 (Mongle)

도식 규칙: 제목을 질문으로 쓸 것, 화살표에 의미를 적을 것, AS-IS/TO-BE는 같은 위치에서 비교할 것,
모든 도식에 캡션을 붙일 것. 도식은 SVG viewBox 비율을 유지하며 박스 너비에 맞춰 축소되어, 좁은 화면에서도 도식 내부에 가로 스크롤이 생기지 않습니다.

## 적용한 디자인 기준

레퍼런스 실측값을 기준으로 잡았습니다.

- **섹션 리듬** 96 → 128px, 컴포넌트 간격은 4px/8px 배수
- **읽기 폭** 본문 최대 1040px, 콘텐츠 셸 1400px, 목차 220px. 히어로 셸은 1180px 유지
- **타입** 본문 15~16px / 1.72, 섹션 라벨 13px 대문자 + 0.16em 자간, 제목 -0.02~-0.035em 트래킹
- **색** 배경 1 + 본문 1 + 보조 회색 3단 + 강조 1. 계층은 색이 아니라 불투명도로
- **목록** 상시 카드 대신 헤어라인 경계선. hover 시 이웃이 아니라 대상만 반응
- **모션** 150~300ms `cubic-bezier(.4,0,.2,1)`. `prefers-reduced-motion`이면 전부 정지
- **상호작용** 깊이 토글, 설계 판단 팝업, 장애·예방 개선 팝업, 읽기 진행률, 흩어진 3D 기술 로고 필드

## 의도적으로 뺀 것

휴대폰 번호, 집 주소, 생년월일, 희망 연봉은 넣지 않았습니다(공개 페이지 기준).
회사명과 공개 가능한 수치만 사용했고, 코드·내부 문서·고객 데이터는 포함하지 않았습니다.

## 아직 안 한 것

1. **OG 이미지 PNG** — `og-image.svg`는 코드 기반 미리보기용입니다. 카카오톡·슬랙 등 일부 크롤러는 PNG만 인식하므로, 배포 전에 1200×630 PNG로 변환해 `og-image.png`로 두고 메타를 바꾸면 호환성이 높아집니다
2. **영문 버전** — 외국계 지원을 염두에 두면 문단 병기 또는 언어 토글
3. **데이터 분리** — 필요하면 `data.js`를 JSON으로 바꿔 백엔드에서 내려줄 수도 있습니다

## 초기 버전 검증 기록

- 렌더링: 시스템 10 / 설계 판단 팝업 15 / 장애·실험·예방 개선 팝업 7 / 런북 5 / 스택 6 / 도식 13, 콘솔 에러 0
- 읽기 깊이 전환, 설계 판단·장애 팝업 열기·닫기, 목차 활성화, 진행률 동작 확인
- 도식 13개 텍스트가 노드 밖으로 넘치지 않고 viewBox를 벗어나지 않음 (좌표 검사, 이슈 0)
- 도식 13개 내부 가로 넘침 없음 (1440 / 1024 / 768 / 390px), SVG 텍스트가 viewBox 안에 포함됨
- 가로 스크롤 없음 (1440 / 768 / 390px), 인쇄 시 전 깊이 펼침 + 흰 배경 전환
- 본문 초기 렌더 외부 요청 0건, 3D 그래프는 첫 화면 렌더 후 필요한 모듈만 지연 요청
